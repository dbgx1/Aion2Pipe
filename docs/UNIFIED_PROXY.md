# 统一独立代理

2026-09-30：实时功能的数据入口统一到 `QueryProxy`，生产程序不再链接旁路 `Capture` 实现。无需 DLL 注入、游戏进程写入、调试器或密钥文件。仅查询进程名和连接归属。

## 功能与数据来源

| 功能 | 统一后的实现 | 验证 |
|---|---|---|
| 游戏世界握手与主动查询 | 代理 RSA 握手、双发送状态、串行资料查询 | 先前真实游戏查询成功；本地独立 OpenSSL/ARC4 双端集成 |
| 登录消息 | TCP 13700 原样转发，代理记录完整帧，按 Login 配置解析 | 本地真实 WinDivert 双向转发测试 |
| HEX、字段、拆包、LZ4、配置查看 | 原始传输正文与自动明文记录，同方向消息流 | 核心协议回归、原生 UI 回放 |
| 所有已支持类型的周围对象 | 同一代理连接的入站消息、按连接 ID 隔离 | 11762 项对象回归、本地自身出现消息回放 |
| 自身位置 | 自动解密的客户端移动上报 + 同连接自身身份 | 本地上报 X=42→99，回放及 UI 最终 X=99 |
| 玩家资料历史结果 | 会话保留工具请求及服务器响应（过滤前），只读回放 | 原生 UI 回放成功显示字段，查询按钮禁用 |
| 原始 IP 与 PCAP | 同一代理 NETWORK 句柄记录改写前的两个 TCP 连接，不另开旁路抓包 | 真实 WinDivert 集成中 PCAP 导出、载入逐包字节相同 |
| 对象 JSON、BIN | 从同一明文及对象模型导出 | 既有导出路径、核心模型回归 |
| 会话保存与回放 | `.a2session`，保留明文、传输正文、连接 ID、方向、工具来源及不完整标记 | 往返、逐字节截断、越界、坏版本检查 |
| 命令行报告 | `protocol_report sample.a2session report.jsonl` | 代理会话直接生成消息/字段，无需状态文件 |
| 生命周期与完整性 | 活跃连接阻止退出；最小化继续消费；队列/分析容量触顶不停止转发 | 10005 条客户端帧压力测试，8192 条记录后标记丢失，查询与后续通信仍成功 |

默认世界端口 13328 可配置；13700 登录端口自动纳入。仅接管目标进程新建的 IPv4 TCP 连接。IPv6、UDP 和加速器外层加密隧道不在当前实时接管范围；历史 PCAP 的原有 IPv6/UDP 分析仍保留。未确认的游戏消息含义、局部出站移动及装备/养成尾部不因本次架构迁移而自动完成。

公开便携版固定使用虚拟网卡/系统路由模式，不识别加速器品牌、进程或本地中继端口。登录服与世界服经过 Aion2Pipe 后沿 Windows 当前路由发送；TCP 443 单独送入聊天分析端口 `18080`，聊天组件的外连同样沿当前路由发送。

## 启动和保存

1. 结束旧游戏连接并退出旧工具，以管理员身份启动新版。
2. 点击“启用独立代理”，再登录游戏。周围对象、收发消息、自身位置自动接收数据。
3. 选择附近玩家，填入查询目标后单次查询。不同连接之间不混用对象或查询目标。
4. 使用“保存代理会话”保存 `.a2session`。此文件含游戏明文，未包含私钥或会话密钥。
5. 先结束游戏连接再关闭代理；关闭后可加载保存的会话进行离线分析。旧 PCAP 仍支持打开，手动状态导入仅用于这些旧数据。

记录代表代理已观察到的应用消息，不能当作原始 IP 抓包；传输正文保留收到时的帧，工具请求则保留发送的编码帧。长度与序号可能因握手替换和工具查询不同于线上 TCP，界面显示的是分析字节偏移。“导出原始 PCAP”仅保存原始 IP 记录；解密消息不会混入 PCAP。消息与原始网络包可在数据包页切换，二者均保存在代理会话文件中。

## 验证证据与验收

- `scripts/test_query_proxy.py`：登录转发、自动 RSA/RC4、插入查询、响应隔离、后续移动、半关闭以及会话回放。
- `scripts/test_query_proxy.py --overflow`：分析队列溢出后继续转发和查询，文件保留不完整标志。
- `artifacts/field-analysis/unified-proxy.a2session`：本机合成会话，仅用于测试，不随发布包分发。
- `artifacts/field-analysis/independent-proxy-integration.json` 与 `unified-overflow-integration.json`：测试结果。
- 新版真实游戏综合验收已完成：用户针对周围对象显示、自身坐标随移动更新、玩家资料查询及游戏不断线三项检查反馈“都正常”。这属于新版的用户实测确认，与先前查询版验证分开记录。

未知首帧或不支持的握手转为原样转发时，同次读取中的后续数据和不完整尾部也会完整保留到观察记录；949 项查询检查包含此回归，未把原样转发字节标为已解密。
