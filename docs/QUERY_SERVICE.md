# 控制台在线查询服务

本版本的“查询服务”会从完整的自身角色出现消息识别当前 `serverId`，并只领取目标 `serverId` 完全一致的在线查询。切换角色、切换区服或重新进入游戏后会自动清除旧区服并重新识别。

同区服有两层保护：调度器只向同服设备派发任务；Aion2Pipe 在真正写入游戏连接前再次核对实时连接的 `serverId`。任一层不匹配都不会发送查询包。

## 本机测试

1. 先退出游戏，再关闭旧工具，避免中断仍依赖旧代理的连接。
2. 以管理员身份运行本包 Aion2Pipe.exe，启用透明代理，然后登录游戏。
3. 在“玩家资料查询”确认连接就绪，能正常手动查询。
4. 打开“查询服务”，点击“启用查询服务”。本机已配置专用身份；账号信息保存在当前 Windows 用户的本地应用数据中，不在压缩包里。
5. 页面显示“已连接”和“可领取查询任务”后，在网页控制台查询一名已知玩家。

界面“已连接”仅说明 MQTT 通信正常；“可领取查询任务”还要求游戏代理连接已就绪且没有正在执行的查询。2026-09-30 已在本机完成真实游戏往返验证；其他机器仍需按上述步骤确认。

## 多机器使用

- 每台机器分配不同客户端标识和专用查询密码。不能复制本机 settings.json：密码使用 Windows 当前用户加密，其他机器无法解密。
- 管理员用源码目录 scripts/provision-query-device.ps1 创建身份和限定权限。默认只创建账号并加密保存在管理员本机；-InstallLocal 仅用于安装到当前机器。
- 将该设备自己的标识和密码交给对应使用者，在“查询服务”填入后启用。Broker 管理 API 密钥不能交给客户端。
- 管理员可运行 `scripts/show-query-device.ps1 -ClientId 设备标识 -RevealPassword` 查看该设备专用密码。只将这一台设备的凭据交给对应使用者；不带 `-RevealPassword` 时仅显示标识。
- 启动程序不会自动启用查询服务。停止查询服务不会关闭游戏透明代理。

## 调度行为

每客户端同时最多一个查询，和手动资料查询共用忙碌检查；无固定发送间隔，上一笔完成后立即处理下一笔。调度器优先分配空闲客户端，合并同目标并发查询，已确认结果缓存 10 秒。失败最多换一台客户端重试一次，超时和游戏断线返回未知，不推断为离线。

每个任务有独立编号、尝试编号、游戏连接标识和到期时间。重复收到同一次任务不会再次发送游戏查询。仅游戏明确返回的在线字段可以确认在线或离线。

MQTT 状态每约 55–60 秒刷新，状态变化时及时发送。正常停止时会尝试通知调度器暂停分配；断网或强制关闭时，调度器最多 90 秒未收到状态便不再使用该客户端。正在执行的查询若未返回，按任务超时规则处理。

## 当前验证范围

已经验证 MQTT TLS、专用账号权限、消息转发到 Cloudflare、调度状态机、重复结果隔离、网页结果保存校验、客户端启停和单机身份互斥。真实游戏验证包括一次单人查询和一次两人批量查询，共三名角色，覆盖在线和离线结果；网页结果、D1 确认记录及请求完成状态一致。两人批量结果相隔约 6.6 秒。多台真实客户端并发压力验证尚未完成。

另外，真实 MQTT 下的客户端任务校验已覆盖过期任务、重复任务、旧游戏连接和超出范围的角色 ID。这些测试使用空游戏连接，不能替代真实游戏验收。

## 入场就绪修复（2026-09-30）

查询不再仅凭握手成功接任务：必须收到完整自身角色入场消息；切场景后等待新的入场消息。无固定查询间隔。查询服务显示最近失败原因和当前游戏连接状态，日志记录 query_timeout 和 query_worker_failed。此版需重新登录建立新连接；不能直接恢复旧连接上已超时的查询，以免迟到响应错配。

## 2026-10-01 内置查询凭据版本

查询密码与其配套的客户端标识已编译进程序，界面不再提供密码输入，客户端标识只读。旧设置中的密码不再读取，新保存的 settings.json 仅包含标识和会话计数。每次启动仍需点击“启用查询服务”。

私有构建输入由 scripts/embed-query-credential.ps1 从当前 Windows 用户已有的查询凭据生成，位于已忽略的 private/query_credential.hpp，不随发布目录分发。运行程序不需要该文件，也不需要 DPAPI 密码文件。更换凭据需重新生成并编译。便携版内置相同查询凭据，服务端必须按不同运行会话分别登记，不能用这份共享标识比较不同电脑的启动计数。

## 多电脑区服同步（v13.2）

修复共享内置查询标识导致较低启动计数的电脑被调度器忽略的问题。调度器对便携版按会话登记、保留顺序检查，并分别处理任务占用、回执与重试；独立设备凭据保留原有启动计数检查。此服务端兼容修复对旧版客户端同样有效。

新版主程序每两秒把当前有效游戏连接的区服写入本机 `game-server-status.json`，聊天组件通过父进程提供的路径读取后上报控制台。无需先在聊天中发言。断开连接、多个区服无法唯一确定、文件超过 15 秒未更新时，上报待识别，避免沿用上一个角色的区服；不会改写聊天鉴权身份。控制台通常在下一次心跳时更新。

## 查询失败诊断（2026-10-01）

游戏返回非零结果码时，客户端通过 `game_query_failed:<结果码>` 保留原因，状态为未知；错误响应中的默认在线字段不能作为在线证据。截断响应仍属于协议错误。

调度器兼容旧版 `game_query_failed`。目标被游戏拒绝不再把整个客户端标为不可用；只有相同 `serverId` 的其他可用客户端可以重试。没有同服客户端时返回未知，并明确显示“当前没有同区服查询客户端”。

现场对照：同一连接查询 2201 / wangjw98 成功返回在线，查询 1305 / Lynae 返回 6437。应先核对查询客户端与目标所在大区；6437 的准确官方含义尚未确认，不能将此码直接解释为离线或确定的跨区错误。详细错误码需要运行本次新构建，服务端等待修复对旧客户端也生效。
