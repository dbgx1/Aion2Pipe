# 加入军团页面协议分析（2026-10-01）

## 结论与验证范围

已通过 2026-09-30 转储的 IDA 反编译、协议反射和运行中 AION2.exe 的只读代码核对，定位截图中 Join Legion / List 的推荐列表与按名称搜索接口。尚未采集这两类接口的真实请求响应进行回放验证；分析阶段没有发送请求或修改游戏内存；后续调试页实现见文末。

| 功能 | 客户端请求 | 服务端响应 | 请求正文 |
| --- | --- | --- | --- |
| 推荐军团列表 | `0x8A06 GuildRecommendedList_RQ` | `0x8A07 GuildRecommendedList_RS` | `u8 order`；原生页面发送 0 |
| 搜索军团 | `0x8A08 GuildSearch_RQ` | `0x8A09 GuildSearch_RS` | 军团名称字符串：字节长度 varuint + UTF-8 字节，无末尾 NUL |

`EGuildOrderRule` 的 0 为 MemberCount（人数），1 为 Ranking（排名），2 为 Max（枚举边界，不应作为有效参数）。上述格式不包含消息头、连接编码和加密层。

## 响应字段

两类响应共用 `0x14920E880` 读取函数：首先读取 u16 结果码（消费者以 0 为成功），随后为 varuint 条目数及 GuildInfo 数组。每条字段顺序如下：

| 字段 | 线格式 |
| --- | --- |
| 军团 ID | u64 |
| 军团名称 | 字符串 |
| 军团长名称 | 字符串 |
| 军团等级 | u8 |
| 军团经验 | u64 |
| 成员人数 | u8 |
| 成员上限 | u8 |
| 徽章 ID | u16 |
| 简介 | 字符串 |
| 入会规则 | u8 |
| 是否已经申请 | packed bool；沿用共享位游标，不可按逐条独立 u8 读取 |
| 申请时间原值 | u64，单位未确认 |
| 阵营 | u8 |

整数由现有协议 Reader 按小端读取。原生内存记录步长为 112 字节，不能当作线格式长度。截图中的名称、军团长、人数/上限、介绍和入会按钮状态均有对应字段。

## 定位证据

以下为当前分析版本的 VA，映像基址 0x140000000；不保证未来版本沿用。

- `0x148FF2C90`：`FNetworkStaticsGame::SendGuildRecommendedList`；写入消息号 0x8A06 和 order=0，随后通过 `0x149129610` 发送。
- `0x1491A5780`：0x8A07 分发；调用 `0x14920E880` 读取，交给 `0x148FF2E60` 更新缓存并触发列表更新事件 0x1D8。
- `0x148FF31E0`：`FNetworkStaticsGame::SendGuildSearchList`；写入 0x8A08，通过 `0x14924CA50` 写入名称。
- `0x1491A58C0`：0x8A09 分发；同样调用 `0x14920E880`，成功时交给 `0x148FF3430`。
- 搜索按钮：`OnClickedGuildSearch` → `0x149D9D310` → `0x149D9E8D0` → 查询管理器 `0x148CABA30`。后者函数体当前不可读；转储中的交叉引用连接到搜索发送函数。
- 默认列表：`0x149D9D270` → `0x149D9E700` → `0x148FF2C90`。列表模块检查缓存时间，满足刷新条件才发请求，因此重新打开页面不一定产生新请求。
- 枚举表：`0x14DD9E7A0` MemberCount=0，`0x14DD9E7B0` Ranking=1。

反射证据见 `artifacts/field-analysis/guild-reflection-20261001.json`；运行时代码核对见 `artifacts/field-analysis/guild-ui-live-disasm.txt`。

## 与项目现状的关系

`src/game_protocol.cpp` 已有 0x8A1D 的 GuildInfo 列表解析，可复用其字段读取逻辑，但 0x8A1D 的用途尚未确认，不应把它当作当前页面的推荐列表响应。现已分别接入 0x8A07 和 0x8A09，并明确消息名称。

请求中未发现页码、游标或服务器 ID。不能据此承诺可遍历所有军团或跨区服搜索；搜索匹配方式、服务端数量上限及实际范围需要实包验证。截图提示搜索可找到最近建立的 100 个军团，也不能据此认定接口提供全服完整列表。

建议下一步对一次默认列表加载和一次已知名称搜索留存会话，对照名称、人数与简介验证解码，再接入只读军团列表页面及手动刷新/搜索。

## 调试页面实现

已新增“军团查询”独立页：按人数/排名获取列表、名称搜索、列表与响应字段视图、请求状态与响应计数。发送复用经过验证的世界连接和加密状态；与工具内玩家查询、跳跃互斥。5 秒内未到可发送边界则取消排队；发送后等待 15 秒，不自动重试。

响应按连接保存最近一份，不受抓包保留上限影响。游戏原生军团响应也会显示且继续转发给游戏，协议没有请求编号，因此页面不保证某条响应属于某次工具请求。名称输入上限 256 UTF-8 字节为工具调试边界，并非已验证的服务端限制。

可打开含 0x8A07 / 0x8A09 的代理会话进行只读回放。启动参数 `--guild-page` 可直接选中该页。自动测试覆盖推荐/搜索响应、长字符串、变长帧头、无效请求、插入请求后双向编码同步；真实服务器查询仍待人工验证。
