# 跳跃数据包分析

核对日期：2026-09-30。结论来自现有真实抓包的重新解码与 IDA 中原生序列化函数核对；本次没有向游戏发送动作，也没有修改运行中的游戏或代理。

## 已确认的消息

| 方向 | 消息号 | 名称及作用 |
|---|---|---|
| 客户端 → 世界服务器 | 0x3702 | CharGravityStart_RQ，开始/切换重力运动；包含可选的 `_is_jump_up`，不能把每条 3702 都计为起跳 |
| 客户端 → 世界服务器 | 0x3703 | CharGravityUpdate_RQ，空中位置、朝向、速度和客户端时间更新 |
| 服务器 → 客户端 | 0x371E | CharGravityStart_NT，携带实体键的重力运动通知 |
| 服务器 → 客户端 | 0x371F / 0x3720 | 重力运动的绝对快照 / 位置增量通知 |

服务端通知是否回传自身，不能从消息定义推断。本次轨迹分析使用客户端出站消息。

## 0x3702 的布局

消息号为 u16LE。以下顺序从消息号之后开始：

1. u8 可选字段位图 flags。
2. flags bit 0：u8 `_gravity_mode`，枚举名称未确认。
3. 三个 f32LE：位置 X、Y、Z。
4. f32LE：朝向 `_rotate_dir`，单位未确认。
5. 三个 f32LE：速度 X、Y、Z。
6. flags bit 1：局部坐标结构，当前客户端解析器遇到此分支会停止，不把后续字节套用普通世界坐标布局。
7. flags bit 2：布尔位 `_is_jump_up`。
8. flags bit 3：u64LE `_springboard_id`。
9. flags bit 4：布尔位 `_dead_reckoning_on`。
10. u64LE `_client_time`，时基未确认。

flags 表示字段存在性，后续布尔位才是对应值。布尔字段共享位游标；不能把两个布尔字段各当成一个独立字节，即使中间存在跳板 ID 也不能重置游标。

原生证据：0x85B2CF0 明确构造消息号 0x3702，调用 0x92C5B00。后者按上述顺序写入。反射 EDF9650 给出 CharGravityStart_RQ 与 `_is_jump_up` 等字段名称。0x92C5EB0 则是 3703 的写入器。地址采用当前 IDA 数据库地址，不能直接作为运行时绝对地址使用。

## 真实样本的起跳帧

源文件：`artifacts/self-movement-live-2/cipher-session.pcap`，使用同目录已有历史会话快照重新解码。该快照只用于这份离线样本，不是当前独立代理的运行依赖。

重解码得到 42 条 3702、135 条 3703，另有 24 条 3700、66 条 3701。42 条 3702 全部完整消费，其中：

- 21 条 flags=0x14，`_is_jump_up=true`，起始速度 Z=1000。
- 21 条 flags=0x11，没有 `_is_jump_up` 字段；不能计为新的主动起跳。
- 1000 是该样本的原始速度值，不是所有角色、技能、场景通用的跳跃常量；物理单位未确认。

第一条起跳在抓包记录 372；解码后的完整应用帧长 41 字节。下面偏移从整个解码帧开头算起，包含 1 字节长度前缀；这些偏移只适用于该 flags=0x14 样本。

| 帧偏移 | 宽度 | 字段 | 样本值 |
|---|---|---|---|
| 0 | 1 | ULEB 长度前缀 | 44；按协议换算总帧长 41 |
| 1 | 2 | 消息号 | 0x3702 |
| 3 | 1 | flags | 0x14 |
| 4 / 8 / 12 | 各 4 | X / Y / Z | -106567.273 / -94380.4609 / 22808.248 |
| 16 | 4 | 朝向 | -29.6862049 |
| 20 / 24 / 28 | 各 4 | 速度 X / Y / Z | 447.406647 / -255.053497 / 1000 |
| 32，bit 0 | 1 位 | 向上跳跃 | true |
| 32，bit 1 | 1 位 | 航位推算 | true |
| 33 | 8 | 客户端时间 | 1790672826444 |

## 一次真实轨迹

时间是抓包到达时间相对第一条起跳的差值，不等于严格的游戏模拟时间；应用帧的客户端时间另行保存在 JSON 证据中。

|---|---|---|---|---|---|
| 0 | 372 | 3702 | 22808.248 | 1000 | 明确向上起跳 |
| 117.875 | 381 | 3703 | 22926.0156 | 684.910889 | 上升 |
| 237.939 | 389 | 3703 | 22991.7676 | 415.565521 | 上升、竖直速度降低 |

| 657.711 | 419 | 3703 | 22967.3984 | -531.5578 | 下落 |

这是一条边移动边跳的轨迹，不是原地单次跳跃控制实验。最高位置比起跳位置高约 221.83 个原始坐标单位。模式 2 在该轨迹中出现在下降阶段，但尚未证明枚举名称就是“下落”。落地后继续移动的例子以 3700 恢复；不能据此断言原地落地也发送同一包。3718 的停止路径仍未完整解释。

## 与主动发送和 AFK 的关系

目前能够识别并解析跳跃链路，但本次没有验证单独发送 3702 能使服务器完成一次跳跃，也没有验证其能重置 AFK。真实动作包含起跳、空中更新、转入下落及落地后的状态衔接；位置、速度、客户端时间和当前会话编码状态都有上下文。固定重复历史密文或只改一个布尔位，不能视作等价的正常跳跃。
