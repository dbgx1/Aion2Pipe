# 玩家资料上报

打开“角色上报”页，检查默认填写的控制台地址及上传令牌，点击“开始上报”。使用 `POST /api/characters/upload` 和 `Authorization: Bearer ...`，发送 `{ "characters": [...] }`；网页端无需新增接口、数据库迁移或重新部署。

固定仅采集实时独立代理中的周围玩家，不含自身（包括识别为玩家的拟态角色）。NPC、怪物、环境对象、示例和离线回放均不采集。角色需要已确认的名字、服务器 ID、角色数据库 ID；缺少身份的记录跳过。当前上传：姓名、服务器及角色数据库 ID、已知等级、公会、种族、性别、整体装备等级、战斗力。不会猜测职业，也不上传坐标、HP、原始包、游戏登录数据或会话密钥。64 位角色 ID 保持十进制字符串；超出 JavaScript 安全整数范围的战斗力暂不上传。

## 去重与重试

- 唯一键为控制台地址 + 服务器 ID + 角色数据库 ID。SHA-256 仅涵盖已知资料，坐标、HP、包号和时间不参与。
- 默认积累 60 秒再自动上传，成功后间隔 60 秒上传下一批，每批最多 200 人、约 450KB；相同资料跳过，资料变化才上传新版本。字段未采集到时保留本地已知值。
- 本地 SQLite 使用 WAL 和完整同步，成功指纹及待上传资料跨重启保留。最多保存 100000 个角色，数据库页面上限约 128MiB（WAL 额外占用空间）；内存交接队列最多 10000 个身份。满额或磁盘错误在页面显示，不阻塞游戏代理。
- HTTP 200 且 `ok=true`、`received` 和 `written` 均等于发送条数，才确认整批。上传期间变化的角色仍保留待传版本。
- 网络错误、408、429、服务端错误按退避重试；429 的 Retry-After 被遵守。401/403 暂停网络上传，修正令牌后点击“重试失败”。其他 4xx 隔离整批，避免无限重试错误数据。
- “立即上传”跳过当前等待；“重试失败”重新启用失败记录。网页端原接口没有事件去重确认，网络丢失响应后可能重发；其 `(server_id,character_id)` UPSERT 会更新同一角色，不创建重复角色。
- 暂停阻止后续请求，正在执行的请求可能已到达服务端；已入队的资料仍保留。固定范围版使用独立缓存命名空间，旧版可能包含自身角色的待传记录不会被继续上传。

## 本地数据和凭据

数据位于 `%LOCALAPPDATA%/Aion2Pipe/report/`：`character-report.db` 保存队列和成功记录，`report-config.json` 保存地址及 Windows DPAPI 加密的令牌。不要将这些个人运行数据打包发给其他人。每次启动默认暂停，需要在上报页手动启用。同一 Windows 用户仅允许一个实例占用上报库。普通远程地址要求 HTTPS，本机测试允许 HTTP；禁止跟随重定向发送令牌。

## 现有接口的边界

按要求直接沿用网页接口，其部分字段缺失会覆盖已有资料为空或 0（如职业、头像、未知等级等）；客户端并不能保证保留网站上由其他来源补充的全部字段。可空战斗力、性别、装备等级按现有服务端规则保留旧值。未知公会与明确空公会在本地有所区分，但服务端原接口仍按其既有覆盖规则执行。此版本不增加服务端逐字段合并或跨采集端时间冲突处理。

## 验证

`character_report_tests` 验证身份筛选、字段转换、SHA-256、同角色去重、变化上传、旧版本确认、控制台隔离、失败隔离、重启恢复。

`node tests/web_upload_integration.mjs E:/project/aion2web` 用网页现有的真实上传路由、解析器和保存逻辑，配合隔离的内存 SQLite，接收 C++ 客户端真实 WinHTTP 请求；验证暂时失败重试、成功上传、资料更新、重启去重和令牌加密。不会请求线上控制台。

控制台默认地址为 `https://mmorpgchat.com`；已保存的非空设置优先于版本内置默认值。上报范围固定，不再提供选择器。

当前分发版已填入用户提供的默认上传令牌（输入框隐藏显示），无需首次手动填写；本地保存设置优先。固定只上报周围玩家，上报开关仍需手动启用。
