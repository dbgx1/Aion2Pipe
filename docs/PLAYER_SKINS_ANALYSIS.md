# 玩家时装分析（2026-10-01）

用户确认截图来自其他玩家资料页。现已接入 ImGui 名称和染色展示；历史响应样本不是截图中角色。当前名称表来自 Steam 英文客户端，尚未进行本轮真实染色角色的视觉对照。

## 已确认来源

- `0x3650 ViewChar_RS` 的 `_equip_items` 数组包含时装信息，不能仅把 `_customizing_data` 当成时装列表。
- 新版读取器 `0x1491E5DC0` 调用 `0x1484A1270` 逐项读取 `ViewCharEquipItemInfo`。反射描述符 `0x14EE2B7A8` 对应 `_item_id`、`_equip_item_detail`、`_visual_equip_slot`、`_skin_id`、`_deco_slots`、`_display`、`_default_mesh`、`_override`。
- 单项原生对象 +0x100 为显示部位（线上 u8），+0x104 为时装 ID（线上 u32 LE），随后是变长数量的染色装饰数组和三个共享位缓存 bool。内存偏移不是网络字节偏移。
- 装备详情读取器为 `0x148490170`。其中的 `_equip_slot` 与外层 `_visual_equip_slot` 属于不同枚举，不可混用。
- 周围玩家 `0x3645 CharAppear_NT` 的 `_equips` 为 `EquipBroad`；新版 `0x148489AF0` 读取 `_item_id`、强化等级、显示部位、到期信息、`_skin_id`、染色数组、神石数组、显示标志及特效位。当前正式解析器已经读取其字节，但仍将多个字段标为未知。
- `SkinDecoInfo` 包含染色槽、RGB、移除染色标志、材质 ID、图案 ID、图案颜色、不透明度、尺寸、光泽及金属感字段。反射中部分整数为宽类型，线上实际为 u16；必须按原生读取器处理。

## 真实离线验证

`artifacts/view-char-live-20260930-004006/response-3650.bin` 是此前保存的成功响应。使用新版读取顺序独立解析，基础资料末尾为字节 91，装备数组末尾 4122，外观定制 blob 为 350 字节，连同养成尾部完整消费 4674/4674 字节。

共 39 条装备记录，9 条非零时装 ID。部分例子：

| 部位 | 实际装备 ID | 时装 ID | display |
|---|---:|---:|---|
| 上衣 | 210120001 | 40089201 | true |
| 裤子 | 210220025 | 40089202 | true |
| 手套 | 210520025 | 40089205 | true |
| 鞋子 | 210620001 | 40089206 | true |
| 肩部 | 210420001 | 40029104 | false |
| 披风 | 210720025 | 40068107 | false |

另有实际装备 ID 为 0、时装 ID 非零的装饰部位，不能用实际装备 ID 是否非零筛掉记录。非零时装 ID 不保证当前渲染显示，显示开关和其他覆盖标志需保留。尚未取得时装名称/图标资源表，也未验证 Preview Skin 按钮自身是否产生额外请求。

## 第二轮确认：资料页预览按钮与名称来源

当前 IDA 数据库 `5fd4cc46`（9 月 30 日转储）中，`UAionWidget_OtherCharInfo` 附近的原生注册表 `0x14DA755E0` 将 `OnSkinClicked` 绑定到 `0x1483FF520`。该入口调用 `0x14A063560`：切换控件状态后调用 `0x14A061D40`。

`0x14A061D40` 遍历对象内部缓存映射（+0x4D0、+0x530、+0x580），将对应 ID 写入外观槽控件 +0x3C8 / +0x3CC，并刷新名称、图标和装饰标记。**这一直接调用路径中未见网络查询发送；支持按钮复用已收到的数据这一判断。** 虚调用未全部解析，也未做本轮按钮点击抓包，因此不将“按钮绝无任何附带网络行为”列为已确认结论。仅获取非零时装 ID 已由普通 0x3650 历史样本证明可行。

**第三轮纠正：此前将图标路径误记为名称路径。** 槽控件 `0x14A18C860` → `0x1490411A0` → ItemTable（`0x1487FF7B0`，静态对象 `0x14F297A20`）读取行 +0x30 后调用 `0x1498697A0`，实际查的是 `UI_ItemIconTable`，结果为 `/Game/UI/Resource/Texture/Item/...`。`0x149833380` 读取 SkinTable 的 +92/+100/+108/+116 也是种族/性别图标，不能作为显示名称。

真实名称路径是时装提示控件 `0x149878BE0` → `0x149832F80` → SkinTable（`0x1487FA1C0`，静态对象 `0x14F2975E0`）。种族 1/2 分别选择行 +20/+36（DescLight/DescDark），交给 `0x14983D830`，在 `AION2` StringTable 中按本地化键查找。例如 `Skin_WP_0001_T03_GS_desc_light` 和 dark 版本实际显示为 `Nameless Master (Greatsword)`。行 +12 的 `WP_0001_T03_GS` 是内部键，也不能充当显示名称。

通过 Windows ReadProcessMemory 只读导出当前 PID 23392 已加载的数据，共 1463 条时装、2926 个种族名称全部匹配。语言为 en-US；没有注入 DLL、写游戏内存或执行游戏内函数。过程中调试器暂停请求未成功，后续只读导出在进程运行状态完成。首次导出部分名称未读取成功，第二次完整快照及独立扫描均匹配 2926/2926；发行目录只使用完整结果。

`_display`、`_default_mesh`、`_override` 的字段名称及线格式已经确认，但后两者与最终渲染优先级的完整消费分支尚未验证。UI 应分别保留三个原始标志，而不是把 `_override` 当作“穿戴中”或把 `_default_mesh` 当作“没有时装”。

新增证据：`artifacts/field-analysis/skin-preview-name-chain-20261001.json`。正式客户端代码和发布程序在这两轮分析中均未修改。

## 名称和颜色展示版本

- `scripts/export_skin_catalog.py`：仅用于该构建的只读分析导出，地址不适用于任意版本。
- `data/skin_catalog.json`：Steam 2026-09-30 / en-US，1463 条时装 ID，分别记录天族和魔族名称。旧历史样本 ID 40089201 等不在当前表内，界面显示“名称未收录”，不会猜测或跨服套用。
- `src/skin.*`：发行客户端只加载程序旁的名称 JSON，不读取游戏内存，也不依赖 IDA/x64dbg。
- 玩家资料查询成功后显示“时装名称与颜色”；周围对象选中玩家后的详情也有该区域。名称、部位、ID、每个染色槽的色块/HEX/RGB、图案颜色和显示开关分别展示。种族缺失且两族名称不同时，展示两族名称供辨认。
- 无染色条目显示“默认色（无染色记录）”，移除标志显示“默认色（移除染色）”。默认材质颜色尚未解析，因此不能提供默认外观的精确 RGB。RGB 为网络值，不代表渲染后受材质、光照影响的最终像素颜色。
- 当前仅维护入场消息中的周围玩家外观快照；换装/染色更新通知尚未接入，可重新查询玩家资料刷新。资料页使用本次查询响应的数据。
- 0x3650 装备数组完整读取后才发布 typed skins，保留外观定制与养成尾部未展开的提示。解析失败不发布部分时装；在线状态单独依赖已验证的基础资料前缀，避免扩展染色解析影响既有查询服务。
- `tests/skin_tests.cpp` 覆盖历史响应39条装备/9条时装、跨条目共享 bool、黑色与默认色、图案颜色、逐字节截断、恶意计数、名称缺失和名称表加载失败。

## 列表概览与重点款式

周围列表在名称后增加时装概览、配色、重点时装三列；HP、MP、XYZ 保持在最后。概览从显示标志开启的非零时装中优先展示上衣，其次头盔、主手；悬停列出全部显示款式。件数表示记录数，不推断为同一套装。

配色最多显示五个网络染色色块（包含图案色），其余显示数量；悬停显示款式、部位、槽、HEX/RGB。默认色不伪造为黑色。无外观记录显示“外观资料未获取”。

点击每行“标记”选择重点款式，也可在详情勾选。重点按时装 ID 保存，同款玩家自动高亮。默认开启“重点时装优先”，按命中的不同款式数排序，已显示的重点时装才参与；同数时保持实体编号顺序（重点玩家优先显示仍在场者）。顶部“管理重点时装”可移除不在当前列表的款式。

设置保存到 `%LOCALAPPDATA%/Aion2Pipe/skin-preferences.json`；包括重点 ID 和排序开关。写入失败显示错误并允许重试。该版本使用当前 Steam 名称表，游戏更新后的 ID 兼容性仍需核对。
