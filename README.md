# Aion2Pipe

源码上传范围、本机私有配置和新机器构建准备见 [Git 源码目录说明](docs/GIT_UPLOAD.md)。

## 内置聊天与远程控制

集成发布包只需启动 `Aion2Pipe.exe`。程序会自动启动 `chat_bridge/Aion2ChatBridge.exe`，并在退出时关闭它；不再需要单独运行 `aion2-client.exe`。界面的“聊天控制”页显示运行状态、进程号和最近日志，并可手动重启内部组件。

正常启动后会自动启用独立代理、角色上报和查询服务。Aion2Pipe保持运行时，游戏退出不会关闭这些服务；再次启动游戏后，新建的登录与世界连接会被自动接管，无需再次点击按钮。角色上报仍使用此前在界面保存的地址和令牌；尚未配置或凭据无效时会保留自动启动失败原因，填写正确设置后可手动开始。

内部组件负责 PlayNC HTTPS/WSS 聊天解析、Bearer 和角色信息缓存、私聊/阵营消息发送、MQTT 上报与远程命令、换号控制以及证书检查。世界与登录二进制协议仍由 Aion2Pipe 原生代理处理。

公开版固定使用“虚拟网卡/系统路由模式”，不识别任何加速器进程或本地中继端口。登录、世界和聊天外连统一沿 Windows 当前活动路由运行，由加速器的虚拟网卡/TUN 分流。切换加速器后应重启游戏，以建立属于新路由的连接。

新增“角色上报”页：直接使用网页控制台现有 `/api/characters/upload`，仅上传玩家资料，支持本地持久去重、变化更新和失败重试。配置与接口边界见 [角色上报说明](docs/CHARACTER_REPORT.md)。

Windows x64 / C++20 / WinDivert 2.2.2 / Dear ImGui 1.91.9b / Direct3D 11。

启动顺序为：先让加速器开启虚拟网卡/TUN → 以管理员身份运行 Aion2Pipe → 启动游戏。Aion2Pipe 只接管 `AION2.exe` 的远端登录、世界和 HTTPS/WSS 连接；它自身建立的外连由 Windows 路由送入当前虚拟网卡。程序不检查加速器品牌、主进程、辅助进程或动态端口，因此不同加速器共用同一套路径。可用 `AION2PIPE_WINDIVERT_PRIORITY` 覆盖优先级（无效值回退 2000）。

面向 Aion2.exe 的二进制协议分析工作台。实时功能统一使用独立透明代理：自动握手与发送解密、收发消息、周围对象、自身移动、玩家资料查询、字段/HEX/拆包分析共用同一消息来源，无需注入 DLL、调试器或导入密钥。支持保存 `.a2session` 后离线回放、对象 JSON 与 BIN 导出，并兼容历史 PCAP。迁移范围和验证见 [统一代理](docs/UNIFIED_PROXY.md)。

## 构建和运行

独立“调试”页支持单次或定时间隔重复发送完整原地跳跃序列：无需先手动跳跃，可独立模拟平地原地跳；已有本次原生轨迹时优先使用。按当前连接的停止位置和时间发送起跳、空中更新、下落和停止消息。操作步骤见 [调试页跳跃功能](docs/DEBUG_JUMP.md)。纯网络发送不直接驱动本机动画，真实服务器效果仍待验证。

安装 Visual Studio 的“使用 C++ 的桌面开发”、Windows SDK 和 CMake 组件，然后在项目目录运行：

```powershell
./scripts/build.ps1
./dist/Aion2Pipe.exe
```

脚本从官方仓库下载固定版本依赖并校验 SHA256，运行测试，将程序和驱动复制到 `dist/`。代理需右键“以管理员身份运行”；离线分析不需要管理员。保持 `WinDivert.dll` 与 `WinDivert64.sys` 在程序旁。

在其他机器运行发布包时，需要 Microsoft Visual C++ 2015–2022/更新版本 x64 运行库。最低 Windows 10 x64；此构建在 Windows 10 / MSVC x64 上验证。

1. 目标进程默认为 `AION2.exe`，世界端口默认 `13328`。在登录前点击“启用独立代理”，再建立游戏连接；已有连接不能接管。登录 TCP `13700` 也会通过同一代理记录。
2. 周围对象自动更新；已支持的自身移动上报自动解密并更新已识别的自身对象，无需单独点击捕获或导入状态。
3. 在“数据包分析”中按端点、PID、方向筛选消息，切换明文、传输正文和同方向消息流，使用 HEX 搜索、数值字段解释、自定义拆包、Aion2 结构解析、LZ4 展开和角色配置查看。
4. 在对象详情填入查询目标，再到“玩家资料查询”发起单次查询。原始场景实体 ID 不能代替角色数据库 ID。
5. “保存代理会话”保存全部保留记录及方向、连接、明文、传输正文和不完整标记。使用“打开会话 / PCAP”回放，无需原游戏或会话密钥；资料查询页可查看历史响应，只读，不发送请求。
6. “导出原始 PCAP”保存代理两段 TCP 的真实 IP 包；“导出 BIN”保存选中数据源；“导出 JSON 数组”保存当前连接对象。历史 PCAP 仍可导入导出，其旧密文分析可选用匹配的 `.a2cs`；这不是实时代理的依赖。
7. “停止接管新连接”保留已有转发与分析。先关闭游戏连接，再关闭代理或退出工具。不能在代理运行时加载其他会话或清空正在使用的分析历史。

## 周围对象页面

新增独立的“玩家资料查询”页面：使用 WinDivert 透明代理，自动参与 RSA 握手并同步发送加密，运行时无需调试器、状态文件或 DLL 注入。请在登录游戏前启用代理，再建立新连接；至少验证三条出站消息后，可按服务器 ID 和角色数据库 ID 发起单次查询。周围对象详情可填入查询目标。本地模拟双端的实际 WinDivert/TCP 测试已通过；真实连接完成握手后，用户已确认主动查询资料显示且游戏正常。验证限于本次客户端版本与连接，装备及养成尾部尚未完整解析。操作、依据与限制见 [玩家资料查询](docs/PLAYER_QUERY.md)。可用 `--queries` 直接打开此页。

对象详情现显示 `0x364E` 的最近转向通知（目标角度、上报当前朝向和原因），以及自身 `0x8D02/8D03` 的滑翔/冲刺冷却毫秒值。转向通知不含 XYZ；冷却值标为最近收到的值，不是实时倒计时。这些消息不会刷新自身坐标，未知字段和单位仍明确标注。

收到 `0x8D91` 实体等级更新后，对象列表的普通等级随对应实体刷新；它不含位置，不修改征服者等级，也不会把该实体猜测为自身。

数据包页支持 `0x8D57` 本人最近赛季排名响应，显示结果、玩法、职业、排名记录与下次更新时间。非零结果和未确认含义保留原值；排行榜数据库 ID 不作为周围对象编号。

自身位置自动接收代理解密后的 `0x3700/3701/3702/3703`，与同一连接的入站自身出现消息配对；不再需要 `.a2cs`。缺少自身出现消息时不猜测身份。客户端上报在 JSON 中标为 `position_source: client_report`，不代表服务器确认；缺少更新时提示仍为入场位置。停止消息 `0x3718`、带局部坐标的出站移动分支仍待确认。服务器绝对位置、移动增量继续独立处理。

服务器重力移动 `0x371E/371F/3720` 已加入位置快照和增量更新；攻击位移 `0x372E/372F` 按消息里的当前位置更新，来源为 `server_attack`，目标位置另行显示。攻击位移同时刷新后续增量使用的网络基准，朝向保留原始 float 值并按游戏算法换算为角度。普通、重力和攻击移动的局部坐标结构已解析；载体编号非零时，对象详情显示局部位置/增量和朝向，原世界位置标记为待刷新，等待载体变换或后续世界快照，不直接套用局部 XYZ。服务器的移动拒绝响应 `0x373E/373F/3740` 携带校正 XYZ，收到后更新对应对象并显示“服务器位置校正”，JSON 来源为 `server_correction`。这类响应不保证持续到达，因此不能靠它们保证自身坐标实时刷新。疾跑开关响应 `0x3741/3742` 没有 XYZ。

数据包页支持 `0x3805` 异常状态技能效果和 `0x3801` 技能开始响应：显示接收者/施放者、效果、可选伤害及技能结果。它们不携带 XYZ；伤害事件不会直接覆盖对象 HP。未证实的结果码和剩余伤害用途仍明确标注。

独立的“周围对象”页面默认显示所有已观察到的类型：玩家、NPC/怪物、环境对象、拟态对象，以及只收到更新包而缺少出现包的未分类对象。收到自身出现包 0x3633 后标记“玩家（自身）”，详情显示地图、子区域和已收到的频道信息，JSON 用 `is_self` 区分。可按名称、实体编号、公会搜索，按类型筛选，勾选“显示已离开”查看离开记录。选择行可查看服务器、种族、性别、战斗力、装备等级、翅膀和公会等已确认信息，并跳转到更新该对象的数据包。

代理对象按独立连接 ID 和实体键隔离，重连复用端口不会混淆；历史 PCAP 按世界服务入站连接、连接代次和实体键隔离。历史 PCAP 的标准端口 13328 直接处理，其他端口每两秒尝试按连续三条完整消息识别，其中至少一条须为对象出现、移动、资源或状态更新（包含 LZ4 内层消息；纯心跳不能识别），以支持可观察到明文的加速器转发连接。识别会在日志记录 `world_stream_detected` 和起始偏移。搜索限流起始 64 KiB、单帧 64 KiB、压缩展开 256 KiB；未知布局或只可见加密隧道时不会强行识别。中途捕获只在确认消息边界后跳过前面的残片，不能补回漏捕的对象。完整 TCP 帧及 LZ4 内层消息按顺序处理，重传不重复应用，收到 0x3647/0x3642/0x3635 分别移除玩家/NPC/环境对象。0x3621 准备进入新地图时清空该连接的旧场景列表。新的出现包替换同键旧身份；离开后仅有更新包不会恢复旧身份。默认跟随最新有入站数据的连接，也可手动选择历史连接。

“导出 JSON 数组”保存该连接全部类型的对象，是否包含离开记录遵循勾选项（不受搜索和类型筛选限制）。`fields` 中的字段值保留为字符串，避免角色数据库 ID 和战斗力的 64 位精度损失；`entity_key` 为 u32，位置为数值数组，缺失字段不填 0。

该列表是捕获消息形成的观察快照，不是客户端完整内存对象清单。中途开始、丢包、未知消息、关闭连接和容量上限会影响完整性。坐标暂不标物理单位；普通移动的有符号增量按客户端已确认的 1:1 比例更新网络位置。缺少绝对基准时不从零累加；遇到未解析的坐标系变更、损坏的移动消息或压缩包时，旧位置显示 `*`，等下一次绝对位置恢复。鼠标悬停位置可查看来源和位置更新包，JSON 同时导出这些信息。职业名称与模板 ID 的映射尚未确认，未自动转换。尚未识别的消息仍计入未解析消息；缺少出现包时不推测类型或自身身份。每连接最多保留 10000 个含离开记录的对象，达到限制会提示。

`Aion2Pipe.exe --nearby --open sample.pcap` 直接打开此页；`--proxy --nearby` 启用实时代理（`--capture` 保留为同义参数）。`--smoke --nearby --open sample.pcap` 可无窗口验证该页实际渲染。

“长度拆包”仍提供自定义探索规则。已验证的 Aion2 规则、逐字段依据与未完成部分见 [字段分析进度](docs/FIELD_ANALYSIS.md)。`Aion2Pipe.exe --protocol --open sample.pcap` 直接进入协议页；`--state session.a2cs` 导入对应会话状态。

角色选择响应 `0x3620` 中已验证的 zlib / UTF-16LE JSON 配置会显示为独立的“角色配置字段”表，可查看低血量提醒、地图过滤、聊天等原始设置键。键名来自数据，具体单位和枚举不自动推断；邮件列表和交易服务器状态也有单独结构解析。逐帧 JSONL 报告的 `config` 对象保存展开配置。

`--demo` 打开合成示例。`--smoke` 无窗口渲染示例并输出 `ui-smoke.bmp`，用于检查实际 ImGui/D3D11 渲染。

## 本地诊断日志

程序启动后自动记录日志，不需要额外配置。其他机器出现“周围对象为空”时，以管理员身份启动程序，在登录前点击“启用独立代理”，复现问题并保持 20–30 秒，然后点击顶部“导出诊断日志”，将导出的 `.log` 文件发回即可。正常退出后也保留自动日志。

自动日志默认在程序旁的 `logs` 目录；该目录不可写时改存 `%LOCALAPPDATA%\Aion2Pipe\logs`。鼠标悬停“导出诊断日志”可查看本次日志路径。每次启动创建独立文件，当前会话最多保留三个约 4 MiB 分段；导出按钮按时间顺序合并本次可用分段。以前运行的日志不会自动删除。

记录启动版本、管理员权限、Windows 版本、依赖文件是否存在、驱动错误、网络捕获/进程匹配计数、连接端口、TCP 缺口与中途捕获、帧解析进度、未知消息号、对象数量和页面筛选状态。不记录原始包内容、远端 IP、角色名、聊天内容或会话密钥；日志仅保存在本机，不会自动上传。日志用于区分问题环节，具体字段或版本差异有时仍需另行提供代理会话文件。缺少 DLL/运行库而导致程序尚未启动时，程序本身无法生成日志。

## 捕获与完整性说明

- 生产程序只使用独立代理提供实时消息；旧的旁路捕获仅保留为开发测试工具。当前接管目标进程指定世界端口及登录端口 13700 的新 IPv4 TCP 连接，尚不支持 IPv6、UDP 或任意加密隧道的实时接管。历史 PCAP 的 IPv6/UDP 检查能力仍保留。
- 两段 Windows TCP 连接处理乱序、重传、ACK 和窗口；分析记录是按序消息，不是原始 IP 包，记录中的序号是分析偏移。原始网络包也直接由此代理句柄记录，可切换查看并导出原始 PCAP；不会把解密正文伪装成原始 PCAP。
- 队列最多 8192 条 / 32 MiB；溢出后停止分析记录，但继续转发。每方向流最多 8 MiB；全会话最多 50000 条、正文 128 MiB、流约 128 MiB，触顶停止保留历史包/流并提示，代理连接和实时周围对象继续更新；新坐标、状态、出现/离开消息不依赖历史缓存。未保留的对象更新包不能跳转查看，导出会话标记历史记录不完整。最小化窗口仍消费消息队列。
- `.a2session` 保留不完整标记，回放仍显示缺失风险。会话包含可读游戏数据；只有用户选择保存时才写入文件，不包含 RSA 私钥或会话密钥。
- 历史 classic PCAP（大小端、微秒/纳秒、Raw IP/Ethernet/VLAN）仍支持导入；不支持 PCAPNG。标准 PCAP 不保存 PID、方向和代理明文。
- 未确认的协议字段不会自动赋予含义；客户端上报位置和服务器确认位置保持区分。装备与养成尾部仍未完整解析。

## 验证

构建脚本自动运行协议核心测试：重组、乱序、重传、重叠、序号回绕、分帧、字节序、错误长度、IPv6 UDP、PCAP 往返与畸形输入。

管理员终端可执行 `./build/Release/capture_probe.exe` 验证本机 UDP 捕获，不会向外部服务器发送测试流量。执行 `capture_probe.exe Aion2.exe 10 sample.pcap` 可被动采集游戏 10 秒。

`scripts/debugger.ps1` 通过本机 x64dbg MCP 配置读取连接与认证，不把令牌写入源码。`-Tool GetDebugState` 查看调试状态，`-ListTools` 查看可用接口；`-Config` 指定配置路径。静态与动态验证结果保存在 `docs/`。

参考：[WinDivert 官方文档](https://reqrypt.org/windivert-doc.html)、[Dear ImGui](https://github.com/ocornut/imgui)。第三方许可证见 `THIRD_PARTY_NOTICES.md`。
